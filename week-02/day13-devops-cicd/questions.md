# Day 13 – Revision Questions and Answers

## 1. Why is deployment workflow important?

Deployment workflow provides a structured process for moving software changes from development environments to production environments. It ensures that code is tested, validated, reviewed, and deployed safely. A proper deployment workflow reduces errors, improves software quality, and minimizes risks to business operations.

---

## 2. Why should teams avoid editing production directly?

Teams should avoid editing production directly because production environments contain live business data and are actively used by customers and employees. Direct changes can introduce bugs, cause downtime, break workflows, create security vulnerabilities, and lead to data loss. Testing changes in lower environments first helps reduce these risks.

---

## 3. What problems happen without version control?

Without version control, teams may experience:

- Lost code changes
- Overwritten work
- No change history
- Difficult collaboration
- No rollback capability
- Increased deployment risk
- Poor project management

Version control systems such as Git and GitHub solve these problems by tracking and managing code changes.

---

## 4. Why do enterprise systems require CI/CD?

Enterprise systems require CI/CD because they frequently receive updates from multiple developers. CI/CD automates testing, validation, and deployment processes, ensuring software quality while reducing manual effort. It enables faster, safer, and more reliable software delivery.

---

## 5. Why should testing happen before deployment?

Testing should happen before deployment to identify defects, verify functionality, and ensure software quality. Deploying untested code can lead to production failures, downtime, poor user experience, and business disruptions.

---

## 6. Why do large teams need branches?

Branches allow developers to work independently without affecting the main codebase. They help isolate features, bug fixes, and experiments. Branches reduce conflicts, improve collaboration, and make code reviews easier.

---

## 7. What is rollback and why is it important?

Rollback is the process of restoring a previous stable version of software after a failed deployment or unexpected issue. Rollback is important because it minimizes downtime, protects business operations, and allows organizations to recover quickly from deployment failures.

---

## 8. Why are deployment pipelines useful?

Deployment pipelines automate and standardize software delivery processes. They ensure consistent testing, validation, and deployment procedures. Pipelines reduce human error, improve release quality, and speed up software delivery.

---

## 9. Why is DevOps important in modern software engineering?

DevOps improves collaboration between development and operations teams. It promotes automation, continuous improvement, faster deployments, and better software quality. DevOps helps organizations deliver reliable software efficiently while reducing deployment risks.

---

## 10. Why is enterprise software development different from simple coding?

Simple coding focuses mainly on creating functionality. Enterprise software development involves much more, including:

- Team collaboration
- Testing
- Security
- Scalability
- Deployment workflows
- Monitoring
- Maintenance
- Release management

Enterprise systems must be reliable, maintainable, and capable of supporting large numbers of users.
