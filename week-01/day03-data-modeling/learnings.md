# Salesforce Day 3:  Data-modeling

## Data Modeling Learnings

- Learned the difference between Objects, Fields, and Records.
- Understood how Salesforce stores business data in a structured format.
- Learned that Objects are similar to database tables.
- Fields are used to store specific pieces of information.
- Records represent individual entries inside an object.
- Understood the importance of relationships between objects.
- Learned how one-to-many relationships work in Salesforce.
- Explored Schema Builder for visualizing data structures.

---

## Formula Fields Learnings

- Formula Fields automatically calculate values.
- They reduce manual work and improve accuracy.
- Formula Fields help automate repetitive calculations.
- Learned examples like Percentage Calculation and Remaining Seats.

---

## Validation Rules Learnings

- Validation Rules prevent invalid or incomplete data entry.
- They improve overall data quality.
- Validation Rules help enforce business logic without coding.
- Learned examples like Age Validation and Mandatory Email Validation.

---

## Overall Understanding

- Salesforce uses structured and connected data instead of random spreadsheets.
- Relationships between objects are important for enterprise systems.
- Business processes can be automated using no-code features.
- Salesforce is called a metadata-driven platform because applications can be customized without modifying core code.
